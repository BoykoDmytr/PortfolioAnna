# ANNA FROLOVA TRAVEL — сайт-портфоліо з адмін-панеллю

Особистий сайт тревел-консультантки **Анни Фролової**: українською (`/`) та англійською (`/en/`).
Світлий мінімалістичний дизайн у фірмових кольорах (пісок і бронза), монограма AF з логотипа,
кнопки Telegram / Viber / Instagram / телефон і форма заявки.

Усе на сайті Анна змінює сама через **адмін-панель українською**: тексти обома мовами, фото,
напрямки й ціни, відгуки, сертифікати, порядок блоків, кольори. Технічні знання не потрібні.

Зараз сайт працює **локально на комп’ютері, повністю безкоштовно**: без платних сервісів, без
бази даних і без інтернету (інтернет потрібен лише для сповіщень у Telegram).

> **Важливо:** зараз на сайті **демонстраційний вміст**: фото-заглушки, вигадані відгуки,
> зразки сертифікатів і тестові контакти. Перед публікацією для реальних відвідувачів усе це
> треба замінити (див. розділ [«Перед публікацією: замініть демо-вміст»](#перед-публікацією-замініть-демо-вміст)).

## Що потрібно

- **Node.js 20 або новіший (версія LTS)** — безкоштовна програма, на якій працює сайт.
  Завантажити: <https://nodejs.org/en/download> (оберіть «LTS», встановіть з налаштуваннями за замовчуванням).
  Перевірити, що встановлено: у терміналі виконайте `node --version` → має бути `v20…` або новіше.
- Будь-який сучасний браузер (Chrome, Safari, Firefox, Edge).

> «Термінал» — це програма для команд: на Windows — **PowerShell** (Пуск → введіть «PowerShell»),
> на macOS — **Термінал** (Launchpad → Інші → Термінал).

## Встановлення і запуск

1. Відкрийте термінал **у папці проєкту** (`PortfolioAnna`).
   Windows: відкрийте папку в Провіднику → клацніть правою кнопкою на порожньому місці →
   «Відкрити в терміналі». macOS: перетягніть папку на значок Терміналу.
2. Лише перший раз встановіть залежності:

   ```bash
   npm install
   ```

3. Запустіть сайт:

   ```bash
   npm start
   ```

4. У терміналі з’явиться підказка з адресами:

   | Що | Адреса |
   |---|---|
   | Сайт українською | <http://localhost:3000/> |
   | Сайт англійською | <http://localhost:3000/en/> |
   | Адмін-панель | <http://localhost:3000/admin/> |

5. Щоб зупинити сайт — у вікні термінала натисніть **Ctrl + C**.
   Поки термінал відкритий і сайт запущений, він працює. Після перезавантаження комп’ютера знову виконайте `npm start`.

Якщо порт 3000 зайнятий, запустіть на іншому: `PORT=3001 npm start`
(у PowerShell: `$env:PORT="3001"; npm start`).

## Вхід до адмін-панелі

- Адреса: <http://localhost:3000/admin/>
- Стандартний пароль: **`anna2026`**
- **Одразу після першого входу змініть пароль**: розділ **«Безпека» → «Пароль до адмін-панелі»**.
  Поки пароль стандартний, угорі адмінки показується жовте нагадування.
- Після зміни пароля всі інші входи (наприклад, на іншому пристрої) автоматично завершуються.
- Вхід пам’ятається 7 днів. Після 5 невдалих спроб вхід блокується на 10 хвилин.

**Забули пароль?** Зупиніть сайт (Ctrl + C), видаліть файл `data/private/auth.json` і знову
запустіть `npm start`. Пароль знову стане `anna2026` — увійдіть і одразу змініть його.
(Можна задати свій початковий пароль: `ADMIN_PASSWORD="мій-пароль" npm start` — він діє лише тоді,
коли файлу `auth.json` ще немає.)

## Як редагувати сайт

Ліворуч у адмінці — меню (на телефоні воно відкривається кнопкою ☰):

- **Сторінка → Структура сторінки** — усі блоки сайту згори донизу:
  - перемикач **«На сайті»** показує або ховає блок (наприклад, приховати «Сертифікати», поки немає сканів);
  - стрілки **↑ ↓** змінюють порядок блоків («Головний екран» завжди перший);
  - **«Редагувати»** відкриває вміст блоку.
- **Сторінка → (кожен блок)** — тексти, фото і списки блоку: Про мене, Послуги, Напрямки,
  Як я працюю, Галерея, Відгуки, Сертифікати, Питання та відповіді, Контакти та заявка.
  Там же: чи показувати блок у меню і як він називається в меню.
- **Налаштування**:
  - **Загальне** — назва бренду, логотип (необов’язково — інакше показується монограма AF), текст у підвалі, назва агенції;
  - **Контакти** — телефон, Telegram, Viber, Instagram, email, місто, графік, плаваюча кнопка зв’язку.
    Заповнені контакти самі з’являються на сайті кнопками; порожні — не показуються.
    Telegram та Instagram вводьте **без @** (можна вставити й посилання — адмінка сама його прибере);
  - **Дизайн** — кольорова тема: «Пісок» (фірмова), «Море», «Олива», «Теракота» або «Власні кольори»;
  - **SEO та соцмережі** — заголовок і опис для Google, картинка для поширення в месенджерах;
  - **Тексти інтерфейсу** — підписи кнопок, полів форми, повідомлень.

**Мови.** Кожен текст має два поля поруч: **UA** і **EN**. Якщо англійське поле порожнє,
на англійській версії покажеться український текст (адмінка підкаже, де EN не заповнено).

**Списки** (послуги, напрямки, фото галереї, відгуки, сертифікати, питання…):
«**+ Додати**» — новий елемент; кнопки на картці: **↑ ↓** — порядок, **дублювати**, **видалити**
(з підтвердженням і можливістю скасувати). На комп’ютері картки можна ще й перетягувати мишкою.

**Маленькі хитрощі в текстах:**
- `*слово*` у заголовку → слово стане елегантним курсивом (наприклад, `Подорож *під ключ*`);
- у довгих текстах абзаци розділяйте **порожнім рядком**.

**Збереження.** Кнопка **«Зберегти зміни»** вгорі (або **Ctrl + S** / **⌘ + S**). Після
збереження зміни **одразу на сайті** — відкрийте сайт кнопкою «Відкрити сайт ↗».
«Скасувати» повертає все до останнього збереження. Якщо щось заповнено неправильно (наприклад,
літери в номері телефону), адмінка покаже, яке саме поле виправити, і нічого не зламається.
Якщо закрити вкладку з незбереженими змінами, браузер попередить.

## Поради щодо фото

- **Формати:** JPG, PNG, WebP, AVIF, GIF, до **15 МБ**. Сайт сам зменшить фото (до 2400 px),
  поверне його правильно і збереже в легкому форматі WebP — стискати заздалегідь не потрібно.
- **Фото з iPhone (HEIC)** не підтримуються. Варіанти: надіслати фото собі в Telegram і зберегти
  звідти; або на iPhone: Параметри → Камера → Формати → «Найсумісніший».
- **Яке фото куди:**

  | Місце | Орієнтація і розмір |
  |---|---|
  | Головний екран (фон) | горизонтальне, від 2000 px завширшки, спокійне, без дрібних деталей там, де текст (ліворуч) |
  | Про мене | вертикальне (приблизно 4:5), ваше фото, від 1200 px заввишки |
  | Напрямки | вертикальні (4:5) — краї обрізаються автоматично |
  | Галерея | будь-які; гарно виглядає мікс горизонтальних і вертикальних |
  | Сертифікати | горизонтальні скани або фото, рівні й світлі |
  | Картинка для поширення (SEO) | 1200 × 630 px |
  | Логотип | PNG або WebP з прозорим фоном |

- Найкраще пасують світлі, теплі, «повітряні» фото — під пісочну гаму сайту.
- Фото людей (клієнтів) публікуйте лише з їхньої згоди.
- **Медіатека** — усі завантажені фото. Позначка «На сайті» / «Не на сайті» показує, чи фото десь
  використовується; невикористані можна видалити.

## Заявки та сповіщення в Telegram

Коли відвідувач заповнює форму на сайті, заявка з’являється в розділі **«Заявки»** (з лічильником
нових). Контакт клієнта клікабельний (дзвінок, Viber, Telegram, email). Статуси: **Нова → В роботі →
Завершена**. Адмінка сама перевіряє нові заявки щохвилини.

**Сповіщення в Telegram (безкоштовно)** — щоб отримувати кожну заявку на телефон:

1. У Telegram відкрийте [@BotFather](https://t.me/BotFather) і надішліть `/newbot`.
2. Придумайте назву бота (наприклад, «Заявки Anna Frolova Travel») та ім’я, що закінчується на `bot`.
3. BotFather надішле **токен** (довгий рядок на кшталт `123456789:AAH…`) — скопіюйте його.
4. Знайдіть свого нового бота і натисніть **«Почати» (/start)** — інакше бот не зможе вам писати.
5. Дізнайтеся свій **Chat ID**: напишіть будь-що боту [@userinfobot](https://t.me/userinfobot) —
   він відповість числом «Id».
   _Інший спосіб:_ після кроку 4 відкрийте в браузері
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` — число після `"chat":{"id":` і є Chat ID.
6. В адмінці: **«Безпека» → «Сповіщення про заявки в Telegram»** — вставте токен і Chat ID,
   увімкніть, натисніть «Зберегти» і «Надіслати тестове повідомлення».

Токен зберігається лише на вашому комп’ютері (`data/private/settings.json`) і на сайт не потрапляє.
Сповіщення надсилаються, поки сайт запущений і є інтернет. Якщо Telegram недоступний, заявка
все одно збережеться в адмінці.

## Резервні копії

- **Автоматично:** перед кожним збереженням попередня версія сайту зберігається
  (30 найновіших копій). Розділ **«Резервні копії»** → «Відновити» поверне будь-яку з них
  (поточна версія при цьому теж збережеться — відновлення можна «відкотити»).
- **Вручну:** «Завантажити копію» — файл `.json` з усіма текстами сайту.
  «Відновити з файлу…» — завантажити такий файл назад (наприклад, на іншому комп’ютері).
- **Повна копія всього:** час від часу копіюйте папку **`data/`** цілком (на флешку чи в хмару) —
  у ній тексти (`content.json`), усі фото (`uploads/`), заявки, пароль і копії (`private/`).
  Щоб перенести сайт на інший комп’ютер — скопіюйте проєкт разом із папкою `data/`.

## Як показати сайт на телефоні

Комп’ютер і телефон мають бути **в одній Wi-Fi мережі**.

1. Зупиніть сайт (Ctrl + C) і запустіть так:
   - macOS / Linux: `HOST=0.0.0.0 npm start`
   - Windows (PowerShell): `$env:HOST="0.0.0.0"; npm start`
2. У терміналі з’явиться адреса на кшталт `http://192.168.1.23:3000/` — відкрийте її на телефоні.
3. Якщо Windows запитає дозвіл для Node.js у брандмауері — дозвольте для **приватних** мереж.

У цьому режимі сайт (і вхід до адмінки) бачать усі пристрої в цій Wi-Fi мережі —
тому змініть стандартний пароль і не вмикайте цей режим у публічних мережах (кафе, готель).

## Статична копія сайту (експорт)

```bash
npm run export
```

Створює папку **`dist/`** — готовий сайт з HTML, стилів і фото, який можна викласти на будь-який
безкоштовний хостинг. Особливості статичної копії:

- **форми заявки немає** (немає сервера, який її прийме) — відвідувачі пишуть у Telegram, Viber,
  Instagram або телефонують (ці кнопки працюють);
- **адмінки немає** — редагуєте як і раніше локально, потім знову робите експорт.

Якщо сайт відкриватиметься з підпапки (наприклад `https://<ім’я>.github.io/PortfolioAnna/`):

```bash
BASE_PATH=/PortfolioAnna npm run export
# PowerShell:  $env:BASE_PATH="/PortfolioAnna"; npm run export
```

Інша папка для результату: `OUT_DIR=…`. Файл `CNAME` (власний домен) і папка `.git` у `dist/`
при повторному експорті зберігаються.

## Як опублікувати пізніше безкоштовно

Чесно про варіанти:

### Варіант А (рекомендовано на старт): статичний сайт — безкоштовно

Хостинги: **GitHub Pages**, **Cloudflare Pages**, **Netlify** — безкоштовні, швидкі, з HTTPS автоматично.

- Як оновлювати: змінили щось у локальній адмінці → `npm run export` → завантажили вміст `dist/`
  на хостинг (Netlify і Cloudflare Pages дозволяють просто перетягнути папку в браузері;
  для GitHub Pages — закомітити й запушити).
- Плюси: нуль витрат, нічого не «падає», нічого зламати, адмінка недоступна стороннім.
- Мінуси: форма заявки не працює (лише месенджери й телефон); після кожної зміни — новий експорт.
- Власний домен (наприклад `annafrolova.travel`) — за бажанням, ≈ 10–15 $ на рік; підключається
  в налаштуваннях хостингу. Після публікації заповніть **SEO → «Адреса сайту»** і зробіть експорт ще раз.

### Варіант Б: запустити сам сервер в інтернеті

Тоді адмінка працює онлайн (з будь-якого пристрою), і форма заявки теж.
Але це вже не зовсім «безкоштовно і просто»:

- безкоштовні тарифи (Render, Railway, Fly.io тощо) часто «засинають» і, головне, **стирають файли**
  при перезапуску — а сайт зберігає тексти, фото й заявки у файлах (`data/`). Потрібен хостинг
  з **постійним диском** — найнадійніше невеликий VPS (≈ 4–6 $ на місяць);
- обов’язково **HTTPS** (інакше пароль передається відкритим текстом) — зазвичай через Caddy або Nginx;
- **змініть стандартний пароль до публікації** (або задайте `ADMIN_PASSWORD` перед першим запуском)
  і запускайте з `NODE_ENV=production`;
- за проксі-сервером усі відвідувачі виглядають як одна IP-адреса, тож обмеження «5 заявок / 10 хв»
  діятиме спільно — це варто доналаштувати розробнику;
- регулярно робіть копію папки `data/`.

Для початку радимо **варіант А**, а до варіанту Б переходити, коли знадобиться онлайн-форма.

- [ ] **Контакти** — тестові `+380 67 123 45 67`, `anna_frolova_travel`, `anna.frolova.travel`,
      `hello@annafrolova.travel` → ваші справжні (Налаштування → Контакти).
- [ ] **Фото «Про мене»** — зараз стокове фото іншої людини → ваше фото.
- [ ] **Відгуки — вигадані!** Публікувати вигадані відгуки не можна: це вводить клієнтів в оману
      (і порушує закон про захист прав споживачів). Замініть на справжні відгуки клієнтів
      (з їхнього дозволу) або **приховайте блок** у «Структурі сторінки», поки їх немає.
- [ ] **Сертифікати — зразки** (з позначкою «ЗРАЗОК · SAMPLE») → скани ваших справжніх сертифікатів
      або приховайте блок.
- [ ] **Цифри** («8+ років», «40+ країн», «1500+ мандрівників») і **ціни напрямків** — перевірте, що вони правдиві.

## Структура проєкту

```
PortfolioAnna/
├── server.js               запуск сайту (npm start)
├── src/                    серверна частина
│   ├── schema.js           опис усіх полів сайту (з нього будуються форми адмінки)
│   ├── validate.js         перевірка й очищення даних
│   ├── app.js              маршрути сайту, форми заявки й API адмінки
│   ├── view-model.js       підготовка даних для шаблонів
│   ├── content-store.js    збереження content.json і резервні копії
│   ├── auth.js             пароль і вхід до адмінки
│   ├── uploads.js          завантаження й обробка фото, медіатека
│   ├── leads.js            заявки
│   ├── notify.js           сповіщення в Telegram
│   ├── icons.js            іконки сайту
│   └── config.js           налаштування (порт, папки)
├── views/                  шаблони сторінок (EJS): index.ejs, 404.ejs, partials/…
├── public/                 стилі, скрипт сайту, шрифти, монограма й іконки → /assets/
├── admin/                  адмін-панель (HTML + CSS + JS-модулі, без збірки) → /admin/
├── data/
│   ├── content.json        УСІ тексти і налаштування сайту
│   ├── uploads/            усі фото → /uploads/
│   └── private/            (створюється автоматично, не публікується і не потрапляє в git)
│       ├── auth.json       пароль адмінки (у зашифрованому вигляді)
│       ├── settings.json   токен Telegram
│       ├── leads.json      заявки
│       └── backups/        автоматичні резервні копії

└── test/                   автоматичні тести (npm test)
```

## Для розробника

```bash
npm start          # сервер (http://localhost:3000)
npm run dev        # сервер з автоперезапуском при зміні коду
npm test           # усі тести (node:test)
npm run export     # статична копія → dist/
```

Змінні середовища:

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `PORT` | `3000` | порт |
| `HOST` | `127.0.0.1` | `0.0.0.0` — доступ з інших пристроїв у мережі |
| `DATA_DIR` | `./data` | папка з даними (content.json, uploads/, private/) |
| `ADMIN_PASSWORD` | `anna2026` | початковий пароль (лише коли ще немає `data/private/auth.json`) |
| `NODE_ENV` | — | `production` — кешувати шаблони |
| `BASE_PATH` | — | префікс шляхів для `npm run export` (напр. `/PortfolioAnna`) |
| `OUT_DIR` | `./dist` | папка результату експорту |

Технічно: Node.js + Express 4 + EJS, фото обробляє `sharp`. Без бази даних і без CDN — шрифти
(Cormorant Garamond, Montserrat; ліцензія SIL OFL, файли ліцензій у `public/fonts/`) лежать у
проєкті. Безпека: суворий CSP (жодних inline-скриптів), cookie сесії `httpOnly` + `SameSite=Strict`,
захист від CSRF заголовком `X-Admin-Request`, обмеження спроб входу і заявок, пароль зберігається
як хеш scrypt. Дані зберігаються атомарно (тимчасовий файл → перейменування).
Схема контенту (`src/schema.js`) — єдине джерело правди: сервер перевіряє за нею дані,
адмінка будує за нею форми, шаблони читають `content.json` її структури.
Сервер розрахований на один процес: не запускайте два сервери з однією папкою `data/`.
